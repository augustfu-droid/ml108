## 导语

西安碑林里有一块石碑，正面刻着一幅《禹迹图》，刻石时间是 1136 年。图上没有画山的皴法，也没有画水的波纹，最醒目的是一张铺满全图的**方格网**：横七十多格、纵七十多格，碑上题记写明"每方折地百里"。黄河、长江的走向，海岸线的轮廓，就落在这些方格里。

这种画法叫"计里画方"。它的厉害之处不在画得多美，而在**所有地方都用同一把尺子**：不管是江南还是塞北，一格就是一百里。有了统一的尺子，两地相距多远、谁在谁的哪一边，数格子就知道了。西晋的裴秀总结制图之法，第一条就是"分率"——比例尺；第二条是"准望"——方位。尺子统一，方向统一，地图才能拼起来用。

前八讲，我们走过了很多地方：第1讲认识了"从例子里学"，第2讲认识了数据、特征和标签，第4讲学会把问题翻译成模型，第5—8讲拿起了 Python、NumPy、Pandas 和画笔。可这些地方还是散的。这一讲，我们要画一张把它们连起来的地图。

3. 要做一件事，该去哪个模块找？面对几十种算法，怎么选？

## 9.1　一种语法：scikit-learn 的设计哲学

### 一个工具箱的来历

scikit-learn 最早是 2007 年谷歌"编程之夏"（Google Summer of Code）里的一个项目，由大卫·库尔纳波（David Cournapeau）发起；2010 年，法国国家信息与自动化研究所（INRIA）的几位研究者接手，发布了第一个公开版本。2011 年，团队在《机器学习研究杂志》（*JMLR*）上发表了介绍它的论文；2013 年，又专门写了一篇文章，讲它的**接口是怎么设计的**。一篇讲"接口设计"的论文，说明这件事在他们心里有多重要。

那篇文章总结了几条原则，最核心的是两条：

- **一致**（consistency）：所有对象共用一小套方法，名字和用法都一样；
- **可检查**（inspection）：构造时给的设置、训练后学到的东西，都能直接读出来。

本讲的代码在 scikit-learn 1.9.0 下运行。

### 三种角色

scikit-learn 里，几乎所有东西都是一个**估计器**（estimator）。估计器只需要会一件事：`fit`，从数据里学。在此基础上，又分出两种常用的角色：

| 角色 | 英文 | 必有的方法 | 例子 |
|---|---|---|---|
| 估计器 | estimator | `fit(X, y)` | 所有对象 |
| 预测器 | predictor | `predict(X)`、`score(X, y)` | `KNeighborsClassifier`、`LogisticRegression`、`DecisionTreeClassifier` |
| 转换器 | transformer | `transform(X)`、`fit_transform(X)` | `StandardScaler`、`PCA`、`OneHotEncoder` |

用法永远是三步：**构造**（设定超参数）→ **`fit`**（学）→ **`predict` 或 `transform`**（用）。数据的约定也是固定的：`X` 是二维数组，一行一个样本、一列一个特征（第2讲），`shape` 为 `(n, m)`；`y` 是长度为 $n$ 的一维数组。

### 两个约定：超参数在构造时给，学到的参数带下划线

第2讲说过，**超参数**（hyperparameter）是我们事先定的，比如 K 近邻的 $K$；**参数**（parameter）是模型从数据里学出来的，比如第1讲那排"旋钮" $\boldsymbol{\theta}$。scikit-learn 用两个约定把它们分得清清楚楚：

1. **超参数在构造时给**：`KNeighborsClassifier(n_neighbors=3)`。之后可以用 `get_params()` 读出来，用 `set_params()` 改。
2. **学到的参数，名字以下划线结尾**：`mean_`、`scale_`、`coef_`、`classes_`……**带下划线的东西，只有 `fit` 之后才存在。**

看见 `coef_`，你就知道：这是学出来的；看见 `n_neighbors`，你就知道：这是人定的。

### 转换器：标准化的 fit 与 transform

第6讲我们用 NumPy 手写过标准化。一个特征的第 $i$ 个取值 $x$，标准化后是：

$$
z = \frac{x - \mu}{\sigma}
$$

其中 $\mu$（读作"缪"）是这个特征在**训练集**上的均值，$\sigma$（读作"西格玛"）是训练集上的标准差，$z$ 叫标准分数，意思是"$x$ 离均值有几个标准差"。`StandardScaler` 的口径和第6讲一样，标准差除以 $n$。

**纸笔先算。** 训练集只有一个特征，8 个值：2, 4, 4, 4, 5, 5, 7, 9。

- 均值：$\mu = (2+4+4+4+5+5+7+9)/8 = 40/8 = 5$；
- 偏差：$-3, -1, -1, -1, 0, 0, 2, 4$，平方和 $9+1+1+1+0+0+4+16 = 32$；
- 标准差：$\sigma = \sqrt{32/8} = \sqrt{4} = 2$；
- 新来两个值 11 和 5：$z = (11-5)/2 = 3$，$z = (5-5)/2 = 0$。

再让 scikit-learn 算一遍（`code/l009_api.py`）：

```python
X_train = np.array([[2], [4], [4], [4], [5], [5], [7], [9]], dtype=float)
X_new = np.array([[11], [5]], dtype=float)

scaler = StandardScaler()
print("构造之后，还没学：", hasattr(scaler, "mean_"))
scaler.fit(X_train)
print("fit 之后：mean_ =", scaler.mean_, " scale_ =", scaler.scale_)
print("训练集变换：", scaler.transform(X_train).ravel())
print("新数据变换：", scaler.transform(X_new).ravel())
print("fit_transform 与 fit 再 transform 相同：",
      np.allclose(StandardScaler().fit_transform(X_train), scaler.transform(X_train)))
```

运行结果：

```text
构造之后，还没学： False
fit 之后：mean_ = [5.]  scale_ = [2.]
训练集变换： [-1.5 -0.5 -0.5 -0.5  0.   0.   1.   2. ]
新数据变换： [3. 0.]
fit_transform 与 fit 再 transform 相同： True
```

四件事值得记住：

1. 刚构造出来的 `scaler` 没有 `mean_`——**它还什么都没学**。
2. `fit` 只做一件事：从训练集里量出尺子，$\mu = 5$ 存进 `mean_`，$\sigma = 2$ 存进 `scale_`。
3. `transform` 只用尺子，不再量尺子。所以新来的 11 变成 3，和手算一样。
4. `fit_transform` 是"先 fit 再 transform"的简写，**只该用在训练集上**。

## 9.2　fit、predict、score：预测器

### 用第1讲的五个点

第1讲我们手算过 K 近邻：五个训练点 A(1,1) 红、B(2,2) 红、C(3,4) 蓝、D(5,5) 蓝、E(1,3) 红，查询点 Q(3,3)，$K=1$ 判蓝，$K=3$ 判红。现在交给 scikit-learn：

```python
X1 = np.array([[1, 1], [2, 2], [3, 4], [5, 5], [1, 3]])
y1 = np.array(["红", "红", "蓝", "蓝", "红"])
knn = KNeighborsClassifier(n_neighbors=3)
print("超参数：", knn.get_params()["n_neighbors"], knn.get_params()["metric"])
knn.fit(X1, y1)
print("学到的：classes_ =", knn.classes_, " n_samples_fit_ =", knn.n_samples_fit_)
print("predict([[3,3],[4,4]])：", knn.predict([[3, 3], [4, 4]]))
print("predict_proba([[3,3]])：", knn.predict_proba([[3, 3]]).round(3))
print("score（在训练点上）：", knn.score(X1, y1))
print("set_params 改成 K=1 后预测 (3,3)：", knn.set_params(n_neighbors=1).fit(X1, y1).predict([[3, 3]]))
```

运行结果：

```text
超参数： 3 minkowski
学到的：classes_ = ['红' '蓝']  n_samples_fit_ = 5
predict([[3,3],[4,4]])： ['红' '蓝']
predict_proba([[3,3]])： [[0.667 0.333]]
score（在训练点上）： 1.0
set_params 改成 K=1 后预测 (3,3)： ['蓝']
```

逐行读：

- `metric` 默认是 `minkowski`（闵可夫斯基距离），在默认设置下就是第1讲的欧氏距离（第10讲讲范数时会细说）。
- K 近邻的 `fit` 几乎不"学"：它只是把训练点记下来（`n_samples_fit_ = 5`），再记住有哪几类（`classes_`）。真正的计算发生在 `predict` 时。
- Q(3,3) 最近的三个点是 C、B、E，两红一蓝，判红；`predict_proba` 给出的就是投票比例：红 $2/3 \approx 0.667$，蓝 $1/3$。(4,4) 最近的三个是 C、D、B，两蓝一红，判蓝。
- 把 $K$ 改成 1，Q(3,3) 判蓝。和第1讲手算的结果完全一致。

### score 默认就是准确率

分类器的 `score(X, y)` 先 `predict(X)`，再和真实标签比，返回**准确率**（accuracy）：

$$
\text{Accuracy} = \frac{1}{n}\sum_{i=1}^{n} \mathbb{1}\left[\hat{y}_i = y_i\right]
$$

$\hat{y}_i$（读作"$y$ 帽 $i$"）是模型对第 $i$ 个样本的预测，$y_i$ 是真实标签；$\mathbb{1}[\cdot]$ 叫**示性函数**（indicator function），方括号里的话成立取 1，不成立取 0。整个式子就是"猜对的个数除以总数"——第6讲的 `(预测 == 真实).mean()`。

上面在训练点上得到 1.0，**不说明任何问题**：用考过的题再考一次，满分很正常。准确率一定要在没见过的数据上算。

### 换模型，只换一行

统一接口的好处，在换模型时最明显：

```python
model = KNeighborsClassifier(n_neighbors=5)     # 换成 LogisticRegression() 或 DecisionTreeClassifier()
model.fit(X_train, y_train)
model.predict(X_test)
model.score(X_test, y_test)
```

只改第一行，后面三行一个字不用动。这就是"一种语法"的意思。不同的模型学到的东西不一样：逻辑回归学到权重 `coef_` 和截距 `intercept_`，决策树学到一棵树（`tree_`），但 `fit`、`predict`、`score` 的用法完全一样。

### fit 返回模型自己

你可能注意到上面有一行 `knn.set_params(n_neighbors=1).fit(X1, y1).predict([[3, 3]])`，一口气连了三个方法。能这样写，是因为 `fit` 学完之后**返回模型自己**，`set_params` 也一样。所以 `model = KNeighborsClassifier(5).fit(X_train, y_train)` 是很常见的一行写法：构造、学习一步到位，拿到的就是学好的模型。

还有一个容易踩的坑：**同一个对象再 `fit` 一次，会把上一次学到的东西全部覆盖。** 它不会"在上次的基础上接着学"。想同时保留两个学好的模型，就要构造两个对象。后面交叉验证每一折都要"从头学一遍"，scikit-learn 内部就是先把模型复制一份干净的（`clone`），再去 `fit`。

## 9.3　模块地图与选路的思路

### 常用模块一览

scikit-learn 按"要做的事"分成若干模块。下面这张表是本课程前半程要反复用到的"地图"：

|---|---|---|---|

| `neighbors` | 近邻方法 | `KNeighborsClassifier` | 第37讲 |

| `ensemble` | 集成方法 | `RandomForestClassifier`、`GradientBoostingClassifier` | 第41讲起 |
| `svm` | 支持向量机 | `SVC` | 第46讲起 |

| `metrics` | 评估指标 | `accuracy_score`、`confusion_matrix`、`classification_report` | 第27、31—33讲 |

找东西的口诀：**先想"我要做的是哪一类事"，再去对应的模块里找。** 导入时写全路径，比如 `from sklearn.neighbors import KNeighborsClassifier`，名字本身就告诉你它住在哪。

### 面对几十种算法，怎么选

scikit-learn 官方文档里有一张著名的流程图"选择合适的估计器"（Choosing the right estimator），按"有没有标签""要预测类别还是数值""样本有多少"一路分岔。我们先记住更朴素的四步：

1. **先认路**：有标签、要预测类别 → 分类；预测数值 → 回归；没有标签 → 聚类或降维（第1讲的三种范式）。
2. **先立基线**：最笨的办法能得几分（第4讲）？比如"永远猜最多的那一类"。模型连基线都赢不了，不用往下谈。
3. **从简单的开始**：K 近邻、逻辑回归、决策树这些简单模型，训练快、好解释，先跑一遍。
4. **用同一把尺子比**：同一份划分、同一种评估方法、同一个指标（第4讲"先定指标"），再决定要不要上更复杂的模型。

没有哪个算法在所有问题上都最好。选算法不是猜，是**在同样的规则下比一比**。下面几节，就来建立这套"同样的规则"。

## 9.4　Pipeline：把尺子锁在训练集里

### 第2讲的那句话

第2讲做葡萄酒实验时，我们用了 `make_pipeline(StandardScaler(), KNeighborsClassifier(...))`，当时说：**标准化的尺子只能从训练集来。** 第6讲又提醒了一次：如果用全部数据算均值和标准差，测试集的信息就悄悄漏进了训练过程。

这种"测试集的信息漏进训练过程"的现象，叫**数据泄漏**（data leakage）。测试集的意义，是模拟"将来没见过的数据"。将来的数据，此刻是拿不到的；如果你在训练时用到了它的任何信息，哪怕只是它的均值，测试成绩就不再是"考试"，而是"考前偷看过的考试"。第4讲的"催收电话"，是特征里的泄漏；这里说的，是**预处理**里的泄漏。

### 两种写法

泄漏的写法，往往看起来更"简洁"：

```python
# 泄漏写法：先在全体数据上标准化，再划分
X_all_scaled = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X_all_scaled, y, ...)
```

不泄漏的写法，要记得 fit 只碰训练集：

```python
scaler = StandardScaler().fit(X_train)            # 尺子只从训练集量
model = KNeighborsClassifier(5).fit(scaler.transform(X_train), y_train)
model.score(scaler.transform(X_test), y_test)     # 测试集只被 transform
```

第二种写法是对的，但步骤一多就容易出错：漏写一个 transform，或在测试集上误用了 fit_transform。**Pipeline 把这些步骤打包成一个估计器**：

```python
pipe = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5))
pipe.fit(X_train, y_train)
pipe.score(X_test, y_test)
```

### Pipeline 里面发生了什么

一条 Pipeline 由若干步组成，前面每一步都是转换器，最后一步可以是任何估计器。

- `pipe.fit(X, y)`：第一步 `scaler.fit_transform(X)` 得到 $Z$，最后一步 `knn.fit(Z, y)`；
- `pipe.predict(X_new)`：第一步只做 `scaler.transform(X_new)`，最后一步 `knn.predict(...)`。

**fit 时量尺子，predict 时只用尺子。** 这个规矩被写死在 Pipeline 里，你想犯错都难。更重要的是，Pipeline 本身就是一个估计器，有 `fit`、`predict`、`score`，所以它能被整个交给下面要讲的交叉验证和网格搜索——每一折都会**重新**只在那一折的训练部分上量尺子。这一点，手写的 scaler 做不到。

`make_pipeline` 会自动给每一步起名字，就是类名的小写：

```text
Pipeline 的步骤名： ['standardscaler', 'kneighborsclassifier']
```

用 `pipe.named_steps["standardscaler"].mean_` 可以取出学到的尺子。工程上更完整的 Pipeline 用法（不同列不同处理、自定义步骤），留给第69讲。

## 9.5　交叉验证：不要只考一次

### 一次考试的运气

第2讲我们把 178 瓶酒切成训练集 106 瓶、验证集 36 瓶、测试集 36 瓶，用验证集挑 $K$。可是 36 瓶太少了：测试集上，**一瓶酒就是 2.8 个百分点**（$1/36 \approx 0.028$）。第2讲算过准确率的标准误差：

$$
\mathrm{SE} = \sqrt{\frac{p(1-p)}{n}}
$$

$p = 0.95$、$n = 36$ 时，$\mathrm{SE} \approx 0.036$。换一种切法，分数上下跳三四个百分点是常事。只考一次，分数里有很大的运气成分。

### k 折交叉验证

**k 折交叉验证**（k-fold cross-validation）的做法是：把训练数据平均分成 $k$ 份（"折"，fold），轮流让其中一份当验证集、其余 $k-1$ 份当训练集，训练 $k$ 次，得到 $k$ 个分数 $s_1, s_2, \dots, s_k$。

报告时给两个数。一个是**平均分**：

$$
\bar{s} = \frac{1}{k}\sum_{i=1}^{k} s_i
$$

$\bar{s}$ 读作"$s$ 拔"，表示 $k$ 个分数的均值。另一个是**标准差**，衡量分数在各折之间跳得多厉害：

$$
\mathrm{sd} = \sqrt{\frac{1}{k}\sum_{i=1}^{k}\left(s_i - \bar{s}\right)^2}
$$

这是 NumPy `std()` 的默认口径，也是 scikit-learn 在 `GridSearchCV` 结果里报告的口径；统计学里常把分母换成 $k-1$（第7讲提到过两种口径）。$k$ 很小时两者略有差别，下面的例题两种都算。

每个样本都恰好当过一次验证数据，所有数据都被用上了。最常用的是 $k = 5$ 或 $k = 10$。对分类问题，还要让每一折里各类的比例和整体一致，叫**分层**（stratified）k 折，`StratifiedKFold`。

scikit-learn 里一行就够：`cross_val_score(模型, X, y, cv=5)`，返回 $k$ 个分数组成的数组。`cv=5` 这种写法，对分类器默认就是分层 5 折，但不打乱顺序；本讲统一写成 `StratifiedKFold(n_splits=5, shuffle=True, random_state=0)`，先打乱再分，并固定随机种子，保证结果可以复现。

### 为什么交叉验证一定要配 Pipeline

交叉验证里，每一折的"验证部分"都扮演着一次小测试集。如果你先在全部训练数据上做了标准化，再交给 `cross_val_score`，那么每一折的验证部分都已经参与过量尺子——第2讲的规矩，在每一折里都被破坏了一次。

把 Pipeline 交给 `cross_val_score` 就没有这个问题：每一折，scikit-learn 都会复制一份干净的 Pipeline，**只用那一折的 4/5 训练部分**重新量尺子、重新训练，再去验证剩下的 1/5。五折，就量五次尺子。手写的 scaler 放在交叉验证外面，是做不到这一点的。**Pipeline 和交叉验证，是天生的一对。**

### 纸笔例题：0.94 ± 0.03

**例题**：某模型做 5 折交叉验证，五个分数是 0.97、0.94、0.91、0.97、0.91。求平均分和标准差。另一位同学只做了一次划分，报告测试准确率 0.97。哪个结论更可信？

**解**：

第一步，平均分：

$$
\bar{s} = \frac{0.97 + 0.94 + 0.91 + 0.97 + 0.91}{5} = \frac{4.70}{5} = 0.94
$$

第二步，偏差：$0.03,\ 0,\ -0.03,\ 0.03,\ -0.03$。

第三步，偏差平方和：$4 \times 0.03^2 + 0 = 4 \times 0.0009 = 0.0036$。

第四步，标准差：

- 分母取 $k = 5$：$\mathrm{sd} = \sqrt{0.0036/5} = \sqrt{0.00072} \approx 0.0268$；
- 分母取 $k - 1 = 4$：$\mathrm{sd} = \sqrt{0.0036/4} = \sqrt{0.0009} = 0.03$。

所以可以报告为 **$0.94 \pm 0.03$**（按 $k-1$ 口径；按 $k$ 口径约 $0.94 \pm 0.027$）。程序核对（`code/l009_api.py`）：

```text
均值： 0.94
偏差： [ 0.03  0.   -0.03  0.03 -0.03]  偏差平方和： 0.0036
标准差（除以 k，np.std 默认）： 0.0268
标准差（除以 k-1）： 0.03
均值的标准误 std(ddof=1)/sqrt(k)： 0.0134
```

**讨论：为什么 0.94 ± 0.03 比单次的 0.97 更可信？**

1. **单次 0.97 可能只是运气好的那一折。** 看这五个分数：五次里有两次是 0.97，也有两次是 0.91。只切一刀，你碰到 0.97 和碰到 0.91 的机会差不多。那位同学报 0.97，另一位同学换个随机种子，可能报 0.91——同一个模型，两份报告差了 6 个百分点。
2. **0.94 用上了所有数据。** 每个样本都当过一次验证数据，平均分不依赖某一刀切在哪里。
3. **±0.03 说出了"不确定有多大"。** 单次的 0.97 只是一个点，看不出它会跳多远；交叉验证的标准差告诉我们：换一份数据，分数大约在 0.91 到 0.97 之间晃。如果两个模型的平均分只差 0.01，而标准差是 0.03，就**不能**说谁更好。
4. 平均分本身的波动比单个分数小：粗略地看，均值的标准误约为 $0.03/\sqrt{5} \approx 0.013$。不过各折的训练集大量重叠，分数并不独立，这个数只能当参考，第36讲再细说。

**一个更可信的数，不一定是更好看的数。** 0.94 比 0.97 低，但它更接近模型将来真实的样子。

## 9.6　GridSearchCV：让网格替你试 K

### 计里画方，逐格去试

挑超参数，最直接的办法是把候选值列成一张表（"网格"，grid），每一格都做一次交叉验证，选平均分最高的那一格。这就是**网格搜索交叉验证**，`GridSearchCV`。有两个超参数时，候选值就排成真正的方格，像《禹迹图》上的格子，一格一格地量过去。

```python
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
pipe = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5))
grid = GridSearchCV(pipe, {"kneighborsclassifier__n_neighbors": [1, 3, 5, 7, 9, 11, 15, 21, 31]}, cv=cv)
grid.fit(X_rest, y_rest)
```

三个要点：

1. **参数名用双下划线**：`kneighborsclassifier__n_neighbors` 的意思是"名叫 kneighborsclassifier 的那一步的 n_neighbors"。前半截是步骤名，后半截是那一步的超参数。
2. **训练次数**：9 个候选、每个 5 折，共 $9 \times 5 = 45$ 次；选出最好的 $K$ 之后，默认（`refit=True`）再用**全部**训练数据重新训练一次，一共 46 次。
3. **结果都带下划线**：`best_params_`（最好的超参数）、`best_score_`（它的交叉验证平均分）、`best_estimator_`（用全部训练数据重训好的那个模型）、`cv_results_`（每一格的详细成绩）。

**测试集不参与这个过程的任何一步。** 选 $K$ 用的是训练数据内部的交叉验证；测试集留到最后，只用一次。这就是第2讲"训练—验证—测试"三分法的升级版：交叉验证替代了那一份固定的验证集。

### 最后那个模型，是用什么数据训练的

初学时容易糊涂：交叉验证训练了 45 个模型，最后交出来的是哪一个？答案是**都不是**。那 45 个模型只是用来"打分"的，打完就扔掉；`refit=True` 时，`GridSearchCV` 会拿着选中的超参数，在**全部**训练数据上重新训练一个新模型，存进 `best_estimator_`。`grid.predict`、`grid.score` 用的都是它。

整个流程可以写成一张时间表：

| 阶段 | 用到的数据 | 产出 |
|---|---|---|
| 交叉验证逐格打分 | 训练数据，轮流切成 4/5 训练、1/5 验证 | 每个候选的"平均分 ± 标准差" |
| 重训 | 全部训练数据 | `best_estimator_` |
| 最终考试 | 测试集，**只用一次** | 一个对外报告的成绩 |

真实项目里，测试集成绩报告之后，通常还会把训练数据和测试集合在一起，用同样的超参数再训练一次，作为真正上线的模型——数据越多越好，而它的成绩，已经由前面的测试估计过了。

网格搜索的代价是候选一多，训练次数成倍增长。随机搜索、贝叶斯优化等更省力的办法，以及交叉验证的更多细节，留给第36讲和第54讲。

X, y = wine.data, wine.target

### 第三步：三种模型，同一把尺子

把 K 近邻和两个新面孔放在同样的规则下比：同一份 5 折划分，同一份测试集。逻辑回归和 K 近邻一样对尺度敏感，也装进 Pipeline；决策树按单个特征的阈值切分（第7讲用"酒精度 > 13.5"筛酒，就是一刀这样的切分），对尺度不敏感，不用标准化。

```python
models = {
    "K近邻（标准化）": grid.best_estimator_,
    "逻辑回归（标准化）": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
    "决策树": DecisionTreeClassifier(random_state=0),

for name, model in models.items():
    cvs = cross_val_score(model, X_rest, y_rest, cv=cv)
    model.fit(X_rest, y_rest)
    print("%-10s 交叉验证 %.3f ± %.3f   测试集 %.3f" % (name, cvs.mean(), cvs.std(), model.score(X_test, y_test)))
```

### 第四步：混淆矩阵——错在哪里

准确率只给一个数，**混淆矩阵**（confusion matrix）告诉你错在哪里：行是真实品种，列是预测品种，对角线是判对的，对角线以外是判错的。

```text
混淆矩阵（行=真实，列=预测）：
 [[12  0  0]
 [ 1 13  0]
 [ 0  0 10]]
              precision    recall  f1-score   support

         品种0      0.923     1.000     0.960        12
         品种1      1.000     0.929     0.963        14
         品种2      1.000     1.000     1.000        10

    accuracy                          0.972        36
   macro avg      0.974     0.976     0.974        36
weighted avg      0.974     0.972     0.972        36

```

36 瓶里只错了一瓶：一瓶品种 1 被判成了品种 0。分类报告（classification report）里的两个新词先有个直觉，第31讲细讲：

- **精确率**（precision）：模型说"是品种 0"的 13 瓶里，真是品种 0 的占多少？$12/13 \approx 0.923$。看的是**一列**。
- **召回率**（recall）：真正的品种 1 有 14 瓶，模型找回了几瓶？$13/14 \approx 0.929$。看的是**一行**。
- `support` 是每个品种在测试集里的瓶数；`f1-score` 是精确率和召回率的一种综合（第31讲）。

### 第六步：泄漏写法 vs Pipeline 写法

最后兑现 9.4 节的承诺：真的写一遍"先在全体数据上标准化，再划分"，和 Pipeline 写法比一比。

```python
X_all_scaled = StandardScaler().fit_transform(X)
Xr_leak, Xt_leak, yr_leak, yt_leak = train_test_split(
    X_all_scaled, y, test_size=0.2, random_state=0, stratify=y)
for k in [1, 5, grid.best_params_["kneighborsclassifier__n_neighbors"]]:
    leak = KNeighborsClassifier(n_neighbors=k).fit(Xr_leak, yr_leak).score(Xt_leak, yt_leak)
    honest = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=k)).fit(X_rest, y_rest).score(X_test, y_test)
    print("K = %2d：泄漏写法 %.3f   Pipeline 写法 %.3f" % (k, leak, honest))
```

```text
K =  1：泄漏写法 1.000   Pipeline 写法 1.000
K =  5：泄漏写法 0.944   Pipeline 写法 0.944
K = 15：泄漏写法 0.972   Pipeline 写法 0.972
两把尺子的差别：均值最大相差 0.055 个标准差，标准差最大相差 5.3%
200 次随机划分（K=5）：泄漏减诚实 平均 +0.0006，176 次相同，14 次泄漏更高，10 次泄漏更低
```

**如实说：在这份数据上，差别几乎没有。** 这一刀切下去，三个 $K$ 的成绩一模一样。为了不被一刀的运气骗，脚本又换了 200 种随机划分：176 次完全相同，14 次泄漏写法高一点，10 次反而低一点，平均只高 0.0006，也就是 0.06 个百分点。

为什么这么小？

1. **标准化从数据里学的东西很少**：每个特征只有两个数，$\mu$ 和 $\sigma$。
2. **142 瓶和 178 瓶量出的尺子几乎一样**：均值最多差 0.055 个标准差，标准差最多差 5.3%。尺子只是微微伸缩了一点，K 近邻的"谁离谁最近"几乎不受影响。
3. **它没有用到标签**：泄漏进来的只是测试集特征的大致位置，不是答案。

那 Pipeline 还有必要吗？有。泄漏的大小取决于预处理**从数据里学了多少、学的是不是和标签有关**。换一种预处理，结果完全不同。`code/l009_leak.py` 造了一份**纯噪声**数据：100 个样本、2000 个随机特征，标签是抛硬币，和特征毫无关系。泄漏写法先用全部 100 个样本（连同标签）挑出 20 个"和标签最相关"的特征，再做交叉验证；诚实写法把"挑特征"也放进 Pipeline，每一折只用那一折的训练部分去挑：

```text
标签中 1 的比例： 0.57
泄漏写法：0.810 ± 0.073
Pipeline 写法：0.520 ± 0.051
```

标签明明是抛硬币，泄漏写法却报出了 81%；Pipeline 写法是 52%，和瞎猜差不多——这才是真相。在 2000 个噪声特征里，总有一些碰巧和这 100 个标签对得上；挑特征时看过了验证数据的标签，等于提前把答案写进了题目。特征选择本身的方法，见第67讲。

**结论**：在葡萄酒上，先标准化再划分，碰巧没造成什么损失；可你事先并不知道泄漏会大还是小。Pipeline 的价值，是让"尺子只从训练集来"成为写死的规矩，而不是每次都靠运气。预处理泄漏、目标泄漏、时间泄漏的系统讨论，见第68讲。

## 本讲小结

1. **scikit-learn 的核心是一种统一的语法**：构造（给超参数）→ `fit`（学）→ `predict` / `transform`（用）。换模型只换一行。
2. **超参数在构造时给，学到的参数以下划线结尾**（`mean_`、`scale_`、`coef_`、`best_params_`），只有 `fit` 之后才存在。
3. 转换器的 **`fit` 量尺子，`transform` 用尺子**；`fit_transform` 只用在训练集上。标准化 $z = (x-\mu)/\sigma$ 中的 $\mu$、$\sigma$ 只能来自训练集。
4. **Pipeline 把预处理和模型打包成一个估计器**，fit 时量尺子、predict 时只用尺子，交叉验证的每一折都会重新量，从结构上防止预处理泄漏。
5. **k 折交叉验证报告"平均分 ± 标准差"**，比单次划分更可信：它用上了所有数据，也说出了不确定有多大。分数差距小于标准差时，不能断言谁更好。
6. **GridSearchCV 在训练数据内部用交叉验证逐格试超参数**，测试集只在最后用一次。
7. 收官项目：葡萄酒三品种，基线 38.9%；**两个特征约九成（交叉验证 93.6%，测试 91.7%），十三个特征约九成五以上（交叉验证 95.8%，测试 97.2%）**；先标准化再划分的泄漏在这份数据上几乎看不出来，但在"用标签挑特征"时会把抛硬币吹成 81%。

## 答案与解析

**1. 答案：B。** 以下划线结尾的 `coef_` 是逻辑回归等线性模型 `fit` 之后学到的权重。`n_neighbors`、`max_iter`、`random_state` 都是构造时给定的超参数或设置。

**2. 答案：C。** 尺子只从训练集量（`fit(X_train)`），再用同一把尺子变换两份数据。A 让测试集参与了量尺子，是泄漏；B 给测试集单独量了一把新尺子，两份数据不在同一个坐标里，而且测试集"自己量自己"同样用到了测试集的信息；D 更是直接用测试集量尺子。

**3. 答案：C。** `make_pipeline` 给逻辑回归这一步起名 `logisticregression`，参数名是"步骤名 + 双下划线 + 超参数名"。

**4. 答案：C。** $9 \times 5 = 45$ 次交叉验证训练，加上选出最好的 $K$ 后在全部训练数据上重训 1 次，共 46 次。程序核对：`习题4： 46`。

**5. 答案：错。** 测试集只能 `transform`，用训练集的 $\mu$、$\sigma$。测试集变换后的均值不是 0 很正常——它本来就是"另一批数据"。

**6. 答案：错。** `best_score_` 是最优超参数在**训练数据内部**做交叉验证的平均分，测试集没有参与。测试集成绩要另外用 `grid.score(X_test, y_test)` 算。

**7. 答案：对。** 这正是统一接口的意义。只是决策树不需要标准化，如果原来写在 Pipeline 里，标准化那一步可以去掉（留着通常也不影响决策树的结果，因为标准化不改变同一特征内部的大小顺序）。

**8. 解：**

（1）$\mu = (1+1+7+7)/4 = 4$；偏差 $-3, -3, 3, 3$，平方和 36，$\sigma = \sqrt{36/4} = 3$；测试样本 $z = (10-4)/3 = 2$。

（2）5 个值 1, 1, 7, 7, 10：$\mu = 26/5 = 5.2$；偏差 $-4.2, -4.2, 1.8, 1.8, 4.8$，平方和 $17.64 + 17.64 + 3.24 + 3.24 + 23.04 = 64.8$，$\sigma = \sqrt{64.8/5} = \sqrt{12.96} = 3.6$；$z = (10-5.2)/3.6 = 4.8/3.6 \approx 1.333$。

（3）$z$ 从 2 变成约 1.333，少了约 0.667。测试样本是个偏大的值，把它算进尺子后，均值被它拉高、标准差被它撑大，它自己就**显得没那么极端了**——模型在测试时看到的，是一个被"提前照顾过"的样本。程序核对：

```text
习题8 诚实：mean_ = [4.] scale_ = [3.] z(10) = [2.]
习题8 泄漏：mean_ = [5.2] scale_ = [3.6] z(10) = [1.3333]
```

**9. 解：**

（1）对角线 $10 + 12 + 7 = 29$，准确率 $29/36 \approx 0.806$。

（2）品种 1 的精确率看"预测品种1"那一列：$2 + 12 + 3 = 17$ 瓶被判成品种 1，其中 12 瓶是真的，$12/17 \approx 0.706$。召回率看"真实品种1"那一行：真实 14 瓶，找回 12 瓶，$12/14 \approx 0.857$。

（3）三个品种的召回率：品种 0 为 $10/12 \approx 0.833$，品种 1 为 $0.857$，品种 2 为 $7/10 = 0.700$。品种 2 最低，错的 3 瓶全被判成了品种 1。程序核对：

```text
习题9 准确率： 29 / 36 = 0.8056
  品种0 精确率 10/11=0.9091 召回率 10/12=0.8333
  品种1 精确率 12/17=0.7059 召回率 12/14=0.8571
  品种2 精确率 7/8=0.8750 召回率 7/10=0.7000
```

**10. 参考代码**（完整版见 `code/l009_exercises.py`）：

```python
X, y = load_breast_cancer(return_X_y=True)
X_rest, X_test, y_rest, y_test = train_test_split(X, y, test_size=0.2, random_state=0, stratify=y)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
knn = GridSearchCV(make_pipeline(StandardScaler(), KNeighborsClassifier()),
                   {"kneighborsclassifier__n_neighbors": [1, 3, 5, 7, 9, 11, 15, 21]}, cv=cv).fit(X_rest, y_rest)
lr = GridSearchCV(make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)),
                  {"logisticregression__C": [0.01, 0.1, 1, 10, 100]}, cv=cv).fit(X_rest, y_rest)
for name, g in [("K近邻", knn), ("逻辑回归", lr)]:
    print("  %s 最好 %s 交叉验证 %.3f 测试集 %.3f" % (name, g.best_params_, g.best_score_, g.score(X_test, y_test)))
raw = cross_val_score(KNeighborsClassifier(n_neighbors=knn.best_params_["kneighborsclassifier__n_neighbors"]),
                      X_rest, y_rest, cv=cv)
print("  不标准化的 K 近邻（同一个 K）交叉验证 %.3f ± %.3f" % (raw.mean(), raw.std()))
best = lr if lr.best_score_ >= knn.best_score_ else knn
y_pred = best.predict(X_test)
print("  交叉验证更好的模型的测试集混淆矩阵（0=恶性，1=良性）：\n", confusion_matrix(y_test, y_pred))
print(classification_report(y_test, y_pred, target_names=["恶性", "良性"], digits=3))
```

解读：（1）K 近邻选中 $K = 3$，交叉验证 0.974；（2）逻辑回归选中 $C = 1$，交叉验证 0.978；两者只差 0.004，同样不宜断言谁更好，按规则选逻辑回归。（3）测试集 114 个样本对了 112 个，98.2%；两个错误都是**恶性被判成良性**（召回率 0.952）。在医疗场景里，这种错误比"良性判成恶性"代价大得多——第4讲说的"错误的价格不一样"，第33讲会讨论怎样通过调阈值减少这类错误。（4）不标准化时，同样 $K=3$ 的交叉验证只有 0.930：乳腺癌数据的 30 个特征里，面积类特征动辄上千，和第2讲葡萄酒的脯氨酸是同一个问题。

**11. 参考答案：**

（1）**测试集太小。** 36 瓶里，100% 和 97.2% 只差一瓶酒。按第2讲的公式，$p = 0.972$、$n = 36$ 时 $\mathrm{SE} = \sqrt{0.972 \times 0.028/36} \approx 0.0275$，比两者的差距（0.028）还大一点点。测试集上的 100% 也不意味着"完美"：换一批 36 瓶，很可能就会错一两瓶。程序核对：`习题11 p=0.972 n=36 SE=0.0275`。

（2）**看交叉验证。** 逻辑回归 $0.965 \pm 0.031$，K 近邻 $0.958 \pm 0.013$，平均分只差 0.007，远小于标准差。本讲 9.7 节还看到，$K = 1$ 在这份测试集上也是 100%，可它的交叉验证是九个候选里最低的——36 瓶的测试集连这种差别都分辨不出来。

（3）**更有把握的做法**：用更多折或重复多次的交叉验证（比如换十个随机种子各做一遍 5 折），看两个模型的分数分布；在**同样的每一折**上比较两个模型，看谁赢的次数多、平均赢多少；如果能收集更多的酒，测试集变大，标准误差也会变小。更严格的模型比较方法见第36讲。结论应该写成："在这份数据上，逻辑回归和 K 近邻表现相当，交叉验证准确率都在 96% 左右。"
