# 第4讲　把问题翻译成模型

> 译事三难：信、达、雅。——严复

---

## 导语

1898 年，严复在《天演论》的译例言里写道："译事三难：信、达、雅。"信，是忠实于原意；达，是表达通顺；雅，是文辞得体。

把一个业务问题变成机器学习问题，也是一次翻译。原文是一句人话，"降低坏账""减少客户流失""提高销量"；译文是一个精确的数学问题：预测什么、用什么预测、怎么衡量好坏、有什么不能碰的边界。

翻译得不"信"，模型再准，也在解决一个别人没问过的问题。这是真实项目里最常见、代价最大的失败，而且它通常发生在写第一行代码之前。

这一讲回答五个问题：

1. 怎样把一句业务目标，拆成一个可以建模的问题？
2. 同一个业务问题，可以翻译成哪些不同的机器学习问题？
3. 模型的损失、评估指标和业务目标，是什么关系？
4. 为什么准确率最高的模型，可能最不赚钱？
5. 什么时候，根本不该用机器学习？

---

## 4.1　从一句话到一个问题

### 一个真实的开场

某消费金融公司的负责人说："我们的坏账太高了，用机器学习解决一下。"

这句话还不是一个机器学习问题。它没有说清楚：要在什么时候、对谁、预测什么、预测完了做什么。

### 六个追问

把业务目标翻译成机器学习问题，可以依次追问六个问题：

| 追问 | 要回答什么 | 坏账例子 |
|---|---|---|
| **1. 支持什么决策？** | 模型的输出会改变哪个动作 | 一笔贷款申请：批准还是拒绝 |
| **2. 预测什么？** | 标签的精确定义 | 放款后 12 个月内是否逾期超过 90 天 |
| **3. 何时预测、对谁预测？** | 预测时点和样本单位 | 每一笔申请，在审批时刻 |
| **4. 用什么数据？** | 在预测时点**能拿到**的特征 | 申请表信息、征信报告、历史借还记录 |
| **5. 怎么衡量好坏？** | 评估指标，最好能连到业务价值 | 批准的贷款带来的总利润 |
| **6. 有什么约束？** | 时间、成本、合规、可解释性 | 审批需在 1 秒内完成；拒绝理由需可解释 |

**第一个问题最重要：先问决策，再问预测。** 一个预测如果不会改变任何动作，它再准也没有价值。"预测明天会下雨"有价值，是因为你会因此带伞；如果你无论如何都不出门，这个预测就没有用。

### 预测时点：最容易出错的地方

第4个追问里，"能拿到"三个字要特别小心。

假设训练数据里有一个特征叫"催收电话次数"，它和违约高度相关，模型一用，准确率飙升。可是，催收电话是在**逾期之后**才打的。审批的那一刻，这个特征根本不存在。

这叫**数据泄露**：模型在训练时用到了预测时不可能知道的信息。它会让离线评估好看得不真实，一上线就原形毕露（第68讲）。

**判断一个特征能不能用，只问一句：在做决策的那一刻，我能拿到它吗？**

## 4.2　同一个问题，多种译法

同一个业务问题，可以翻译成不同类型的机器学习问题。以"减少客户流失"为例：

| 译法 | 问题类型 | 标签 | 适合什么决策 |
|---|---|---|---|
| 未来 30 天内会不会流失？ | 二分类 | 是 / 否 | 给高风险客户发挽留优惠 |
| 还有多少天会流失？ | 回归 | 天数 | 规划挽留动作的时间 |
| 谁最可能流失？ | 排序 | 风险分高低 | 客服每天只能打 200 个电话，打给谁 |
| 客户可以分成哪几类？ | 聚类 | 无 | 为不同人群设计不同的服务 |
| 发优惠券，能让谁留下？ | 因果 / 增益建模 | 发券与不发券的差异 | 把券发给"发了才会留下"的人 |

最后一行值得多想一下。预测"谁会流失"，和预测"谁会因为优惠券而留下"，是两个不同的问题。有些客户本来就会留下，发券是浪费；有些客户无论如何都会走，发券也没用。真正值得发券的，是中间那群"可以被说服"的人。**预测结果，不等于预测干预的效果。**

### 常见问题类型速查

| 类型 | 输出 | 例子 | 本课程 |
|---|---|---|---|
| 二分类 / 多分类 | 类别 | 违约与否、图片类别 | 第28—34讲 |
| 回归 | 数值 | 房价、销量 | 第19—27讲 |
| 排序 | 先后顺序 | 搜索结果、风险名单 | 第32讲 |
| 聚类 | 分组 | 客户分群 | 第55—58讲 |
| 异常检测 | 是否异常 | 可疑交易 | 第62讲 |
| 推荐 | 物品列表 | 猜你喜欢 | 第60讲 |
| 时间序列预测 | 未来数值 | 下周销量 | 第103讲 |

## 4.3　三层目标：损失、指标与业务

一个机器学习项目里，其实同时存在三层"目标"：

1. **训练损失**：模型在训练时最小化的东西，比如第1讲的 $J(\boldsymbol{\theta})$。它要求数学上好处理，比如可以求导。
2. **评估指标**：我们用来比较模型好坏的数字，比如准确率、召回率、均方误差。
3. **业务目标**：真正关心的东西，比如利润、坏账损失、用户留存。

三者经常不一致。训练时最小化的是交叉熵（第29讲），评估时看的是准确率，老板关心的是利润。**越往下一层，越接近真正想要的；越往上一层，越便于计算。** 建模的艺术，就是让上面两层尽量忠实地"翻译"最下面那一层。

### 准确率的陷阱

假设贷款的违约率是 5%。一个"模型"什么都不学，对所有申请一律预测"不会违约"，准确率是多少？

$$
\text{准确率} = \frac{\text{判对的笔数}}{\text{总笔数}} = 1 - 5\% = 95\%
$$

95%，听起来很好。可它一笔坏账也没拦住。

**当类别极不平衡时，准确率几乎没有意义。** 永远要先算一下这个"什么都不做"的成绩，它叫**基线**（baseline）。一个模型如果不能明显超过基线，就不值得上线。

### 让指标连上钱：代价敏感的决策

贷款审批的两种错误，代价是不一样的：

- 把一个好客户拒掉了：损失的是这笔贷款本该赚到的利润，设为 $G$；
- 把一个坏客户批准了：损失的是借出去收不回来的本金，设为 $L$。

通常 $L$ 远大于 $G$。设模型预测某笔申请的违约概率为 $p$，如果批准，这笔贷款的**期望收益**是：

$$
\mathbb{E}[\text{收益}] = (1 - p)\,G - p\,L
$$

只有期望收益大于零才值得批准：

$$
(1 - p)\,G - p\,L > 0 \quad\Longleftrightarrow\quad p < \frac{G}{G + L}
$$

这个 $\dfrac{G}{G+L}$，就是**由业务代价推出来的决策阈值**。

**例题**：每笔贷款若正常还款，赚 $G = 1000$ 元；若违约，损失 $L = 20000$ 元。违约概率低于多少才应该批准？

**解**：

$$
p^{*} = \frac{1000}{1000 + 20000} = \frac{1}{21} \approx 4.76\%
$$

也就是说，**只要违约概率超过 4.76%，就应该拒绝**——哪怕这笔申请有 95% 的可能会正常还款。直觉上的"概率过半才判为坏客户"（阈值 0.5），在这里是完全错误的。

这个例子说明了一件事：**阈值不是技术参数，而是业务决策。** 它由错误的代价决定，应该和业务方一起定（第33讲）。

## 4.4　指标会被"玩坏"

### 古德哈特定律

经济学家古德哈特（Charles Goodhart）观察到一个现象，后来被人类学家斯特拉森（Marilyn Strathern）概括为一句话：

> 当一个度量变成目标，它就不再是一个好的度量。

推荐系统如果只优化点击率，就会学会推荐标题耸动、内容空洞的文章；客服如果只考核"平均通话时长"，就会有人匆匆挂断还没解决的问题。指标本来是业务目标的"代理"，一旦被当成目标本身去优化，模型就会钻它的空子。

### 应对方法

1. **主指标 + 护栏指标**：优化一个主指标，同时监控几个不允许变差的护栏指标。比如优化点击率，同时要求用户停留时长和投诉率不能恶化。
2. **离线指标 + 线上实验**：离线评估只是第一关，真正的效果要通过线上 A/B 实验验证。
3. **定期回到第一个追问**：这个指标，还在忠实地反映我们要支持的那个决策吗？

## 4.5　约束：看不见的边界

模型不是在真空里运行的。常见的约束有：

| 约束 | 问题 | 影响 |
|---|---|---|
| **时效** | 要多快给出结果？ | 实时审批往往要求秒级甚至毫秒级，复杂模型可能用不了 |
| **数据可得** | 预测时能拿到哪些数据？ | 决定特征的边界，防止数据泄露 |
| **可解释性** | 需要向谁解释判断理由？ | 信贷、医疗等领域常有监管要求（第70讲） |
| **成本** | 标注、算力、维护要花多少钱？ | 模型带来的收益必须覆盖成本 |
| **公平与合规** | 会不会歧视某些人群？能不能用某类数据？ | 有些特征即使有用也不能用（第107讲） |
| **错误的后果** | 判错一次有多严重？可以挽回吗？ | 决定是否需要人工复核（"人在回路中"） |

## 4.6　问题定义卡

把以上内容浓缩成一张卡片，每个项目开工前填一次。以"减少客户流失"为例：

| 项目 | 内容 |
|---|---|
| **业务目标** | 降低月度流失率，提高客户生命周期价值 |
| **支持的决策** | 每月初，选出 2000 名客户由客服致电并提供挽留方案 |
| **预测目标** | 客户在未来 30 天内是否注销或连续 30 天无交易 |
| **样本单位与时点** | 每月 1 日的每一位活跃客户 |
| **可用特征** | 截至上月末的交易、登录、投诉、产品持有情况 |
| **问题类型** | 二分类，按流失概率排序取前 2000 名 |
| **主指标** | 前 2000 名中真正流失的比例（精确率@2000） |
| **护栏指标** | 挽留成本、客户投诉率 |
| **基线** | 按"最近一次交易距今天数"排序取前 2000 名 |
| **约束** | 每月批量运行即可；客服需要看到简要的风险原因 |

注意"基线"这一行。它往往是一条简单的业务规则。**机器学习要证明的，不是"它能预测"，而是"它比简单的办法好多少"。**

## 4.7　什么时候不该用机器学习

机器学习不是万能的。以下情况，先停一停：

1. **规则清楚、稳定**：税费计算、合同到期提醒，写规则就够了（第1讲）；
2. **没有数据，或者数据代表不了未来**：新业务刚上线、市场环境刚剧变；
3. **没有决策会因此改变**：预测得再准，也没有人会根据它行动；
4. **错误代价极高又无法解释和复核**：此时至少需要人在回路中；
5. **简单基线已经足够好**：多出的一点点精度，换不回复杂度和维护成本。

**会用机器学习，也包括知道什么时候不用。**

## 4.8　动手：准确率最低的，赚钱最多

我们用一份**模拟**的贷款数据来验证 4.3 节的结论。数据由 `make_classification` 生成：20000 笔申请，10 个特征，违约率约 5%。

模型用的是逻辑回归，它能输出每笔申请的违约概率（第28讲会详细讲，这里把它当作一个"会给出概率的黑箱"即可）。

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression

X, y = make_classification(n_samples=20000, n_features=10, n_informative=5,
                           weights=[0.95, 0.05], flip_y=0.01, random_state=7)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=0, stratify=y)
print("违约率：", round(y_test.mean(), 4), "测试集笔数：", len(y_test))

GAIN, LOSS = 1000, 20000          # 好客户赚 1000，坏客户亏 20000

def profit(approve, y):
    return int(GAIN * (approve & (y == 0)).sum() - LOSS * (approve & (y == 1)).sum())

# 基线：全部批准
base = np.ones(len(y_test), bool)
print("全部批准：准确率", round((y_test == 0).mean(), 4), "利润", profit(base, y_test))

# 模型：预测违约概率，比较两个阈值
model = LogisticRegression(max_iter=1000).fit(X_train, y_train)
p = model.predict_proba(X_test)[:, 1]
for t in [0.5, GAIN / (GAIN + LOSS)]:
    approve = p < t
    acc = ((p >= t).astype(int) == y_test).mean()
    print("阈值", round(t, 4), "准确率", round(acc, 4),
          "批准", approve.sum(), "利润", profit(approve, y_test))
```

运行结果：

```text
违约率： 0.0543 测试集笔数： 6000
全部批准：准确率 0.9457 利润 -846000
阈值 0.5 准确率 0.95 批准 5916 利润 225000
阈值 0.0476 准确率 0.743 批准 4290 利润 2631000
```

把三种做法排在一起：

| 做法 | 准确率 | 批准笔数 | 利润（元） |
|---|---|---|---|
| 全部批准（基线） | 94.6% | 6000 | −846 000 |
| 模型 + 阈值 0.5 | 95.0% | 5916 | 225 000 |
| 模型 + 代价阈值 4.76% | **74.3%** | 4290 | **2 631 000** |

**准确率最低的那一行，利润最高，是第二名的十倍以上。** 代价阈值拒掉了更多申请，其中不少其实是好客户，所以"判错"变多了，准确率下降；但它拦住了大部分代价高昂的坏客户。这就是"翻译"的意义：**模型好不好，要用业务的语言来衡量。**

## 本讲小结

1. 把业务问题翻译成机器学习问题，依次追问：**决策、预测目标、时点与样本、可用数据、指标、约束。先问决策，再问预测。**
2. 特征能不能用，只问一句：**做决策的那一刻，我能拿到它吗？**
3. 同一个业务问题有多种译法：分类、回归、排序、聚类、增益建模……译法取决于要支持的决策。
4. 训练损失、评估指标、业务目标是三层东西，要让前两层忠实地翻译第三层。
5. 类别不平衡时准确率会骗人，**永远先算基线**。
6. 两种错误代价不同时，决策阈值是 $p^{*} = \dfrac{G}{G+L}$。**阈值是业务决策，不是技术参数。**
7. 当一个度量变成目标，它就不再是好的度量。用护栏指标和线上实验来防守。

**4. 答案：C。** 99% 的人确实未患病，全部判"未患病"就能判对 99%。但它一个病人也没找出来，这正是准确率的陷阱。

**6. 答案：错。** 离线指标可能和业务目标不一致，也可能存在数据泄露，或线上数据分布与离线不同。需要线上实验验证，并持续监控（第106讲）。

**7. 答案：对。** 规则清楚稳定、数据不足、基线已足够好等情况下，规则可能更简单、更可靠、更易解释。

**8. 解：**

（1）设欺诈概率为 $p$：

- 送去人工调查：无论是否欺诈，都花 500 元调查（欺诈会被查出，不造成损失），期望损失 $= 500$；
- 直接放行：以概率 $p$ 损失 50000 元，期望损失 $= 50000\,p$。

（2）当 $50000\,p > 500$ 时，调查更划算：

$$
p > \frac{500}{50000} = 1\%
$$

（3）$2\% > 1\%$，应当调查。直接放行的期望损失为 $50000 \times 2\% = 1000$ 元，高于调查成本 500 元。

**9. 解：**

（1）流失率 $500 / 10000 = 5\%$，随机选 1000 名，预计覆盖 $1000 \times 5\% = 50$ 名。

（2）精确率@1000 $= 300 / 1000 = 30\%$，是随机选择 5% 的 6 倍。这个倍数常被称为**提升度**（lift）。

（3）召回率 $= 300 / 500 = 60\%$。

**10. 参考代码：**

```python
best = max(np.arange(0.01, 0.51, 0.01), key=lambda t: profit(p < t, y_test))
print("利润最高的阈值：", round(best, 2), "利润：", profit(p < best, y_test))
```

实测结果：`LOSS = 20000` 时，网格中利润最高的阈值是 0.05，利润 2 600 000 元，和理论阈值 4.76%（利润 2 631 000 元）几乎一致。`LOSS = 5000` 时，理论阈值变为 $1000 / 6000 \approx 16.7\%$（利润 4 518 000 元）；网格中利润最高的阈值是 0.19（利润 4 538 000 元），同样在理论值附近。

两者不完全相等，原因有二：一是模型给出的概率不一定完全准确（概率是否"可信"，叫**校准**）；二是测试集有限，利润曲线有随机波动。总的规律是：坏客户的代价变小，就可以放宽审批，最优阈值随之上移。
